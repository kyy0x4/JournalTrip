# UI

- Prefers pagination or separate pages to switch between multiple charts on a dashboard rather than stacking all charts on one view. Confidence: 0.7
- Prefers hiding or blurring chart data until the user selects a required filter first (progressive disclosure), e.g., pick a customer before seeing per-driver data. Confidence: 0.6
- For multi-month date ranges selected in charts, prefers aggregating per month (e.g., Jan–Jun shows monthly bars) rather than per individual date. Confidence: 0.65
- Prefers explicit unit symbols on displays, e.g., showing "%" on percentage values like normal/hypertension/hypotension percentages. Confidence: 0.6
- When a chart's x-axis is a driver name, wants the ability to switch/cycle views within the same chart component (e.g., blood pressure analysis per driver). Confidence: 0.6
- In trend/line charts, days with no data should be treated as gaps that the line connects across smoothly (e.g., `connectNulls` with null values) rather than dropping the line to 0 — an empty day should not create a valley in the trend; the user re-checks the rendered chart after a fix and reports back ("masih ada lembah... coba cek") if a valley still appears, so the fix must truly eliminate it. Confidence: 0.8
- On mobile/narrow tables, prefers compact single-line badges over long uppercase labels that wrap: e.g., a shift badge with a Sun/Moon icon + short "Day"/"Night" plus `whitespace-nowrap` instead of "DAY SHIFT" wrapping into two lines ("DAY" above "SHIFT") and leaving the background pill cut off/ugly ("background biru nya kepotong jadi jelek"). Confidence: 0.6
- For shift badge colors, prefers following the app's existing convention — Day = orange, Night = blue — rather than new colors introduced during a fix; when asked "mending warna orange ga sih atau yg kaya biasanya", switch the badge to match the established scheme instead of keeping the invented one. Confidence: 0.7
- When adding a new UI element to a page (e.g., driver photo avatar in rankings), prefers reusing the visual pattern already used elsewhere in the app ("jadi kaya profile gitu yang ada di p2h gatepass") so pages stay consistent, rather than inventing a new look; explicitly asked to "samain aja" the element with the reference page (P2H/Gatepass). Confidence: 0.75
- Driver avatar/photo in a table row belongs immediately next to the driver's name ("disamping nama banget"), like on the P2H/Gatepass pages — not in a separate column or beside the rank number; expects the driver's actual photo to display (matched by id, fallback by name) rather than defaulting to the initial-letter fallback. Confidence: 0.8
